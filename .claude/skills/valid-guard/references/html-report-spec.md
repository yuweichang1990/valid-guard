# HTML Report Specification — Detailed Reference

This document contains the detailed specification for the interactive HTML report generated by `/vg review`. Referenced from SKILL.md.

## Design Philosophy

This report focuses on **coverage gap analysis and test design review** — the things Valid Guard uniquely provides. For pass/fail execution results, timing, and step-level details, use the Cucumber runner's built-in reporting (`--format html`, `--format json`).

---

## Report Structure

Generate a single self-contained HTML file (all CSS and JS inline, no external dependencies) at `valid-guard/reports/<feature-slug>-review.html`.

Use the template at `valid-guard/templates/report.html` as the base.

The report MUST include the following sections:

### 1. Header

Feature name, generation timestamp, overall risk level, summary metrics (total scenarios, weighted coverage %).

### 2. Scenario Coverage Dashboard

- Progress bar showing scenario coverage (colored: green >= 80%, yellow >= 60%, red < 60%).
- Weighted coverage (using risk weights from config: high=3, medium=2, low=1).
- Breakdown by risk level (high/medium/low) with individual progress bars.
- **Uncovered scenarios highlighted** — this is the primary actionable insight.

### 3. Example Mapping Visualization

For each story, display a card-based layout:
- Story card (yellow) at top
- Rule cards (blue) branching down
- Example cards (green for happy path, red for error, orange for edge/boundary) under each rule
- Question cards (pink) for open questions from the `questions` field

This mirrors the physical Example Mapping card exercise.

### 4. Decision Table Visualization

For each decision table in the plan, render an HTML table with conditions as rows, rules as columns, and actions at the bottom. Highlight which rules have corresponding Gherkin scenarios and which do not.

### 5. State Transition Diagram

For each state machine, render a visual diagram using HTML/CSS (boxes for states, arrows for transitions). Color-code: green for transitions with Gherkin scenarios, red for untested transitions, gray for invalid transitions that need negative tests.

### 6. Scenario Detail Table

- Sortable, filterable table of all scenarios.
- Columns: Name, Type, Risk, Techniques, Status, Gherkin Ref, Tags.
- Filter by: risk level, status, technique, type.
- Each row expandable to show risk rationale and design notes.

### 7. Interactive Controls

- Checkboxes to approve/reject each scenario.
- Dropdown to adjust risk level per scenario.
- Text input to add notes.
- Button to add a new scenario manually.
- "Export Decisions" button that downloads a JSON file with all human decisions.

### 8. Import Flow

After the human exports decisions JSON, they can provide it to Valid Guard. Print instructions at the bottom of the report: "After reviewing, export your decisions and run: `/vg review --apply <json-path>`".

---

## HTML Quality Requirements

- Responsive layout (works on 1200px+ screens).
- Dark mode support via `prefers-color-scheme`.
- Collapsible sections for large plans.
- Sticky header with summary metrics.
- Print-friendly styles.
- Accessible: proper heading hierarchy, ARIA labels on interactive elements, keyboard-navigable.
- Use modern CSS (grid, flexbox, custom properties). No frameworks.
- Use vanilla JavaScript. No frameworks.
